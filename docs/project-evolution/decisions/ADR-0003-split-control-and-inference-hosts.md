# ADR-0003：将控制服务与 H3 推理解耦部署

- 状态：accepted
- 日期：2026-08-31

## 背景

用户的 5800H 本机适合持续编辑和迭代，但不适合作为 H3 模型推理主机。H3 Director Desk 仓库的 README 也定义了控制机与 GPU/ComfyUI 机器分离的架构。

## 决策

- 5800H 本机运行浏览器和 `director/serve.py`，使用 `8088`；
- 有 NVIDIA GPU 和 H3 模型权重的局域网机器运行 ComfyUI，使用 `8188`；
- 默认采用 SSH 隧道 `本机:8188 -> GPU主机:127.0.0.1:8188`；
- 仅在受控局域网中需要简化配置时，才让 ComfyUI 监听 `0.0.0.0:8188`。

## 原因

Director Desk 负责项目和任务编排，ComfyUI 负责节点执行，H3 是被 ComfyUI 加载的模型。分离后可以让本机不断迭代前端/流程，同时把显存密集型工作集中到 GPU 主机。

## 影响

- 本机 `8188` 不是模型端口的本体；没有隧道时它不会自动出现；
- GPU 主机必须先启动 ComfyUI，并准备 H3 节点、模型权重和依赖；
- 参考图片上传、任务轮询和生成结果下载会跨局域网传输；
- 隧道更安全，但需要远程 SSH 账号和密钥授权；直连更简单，但必须限制防火墙，不能暴露公网。
